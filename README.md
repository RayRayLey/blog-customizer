# Blog Customiser
Проект по реализации панели кастомизации страницы блога. Пользователь может открыть сайдбар с настройками, изменить параметры статьи, применить или сбросить их.

## Цель проекта

Реализовать динамическую кастомизацию страницы статьи через UI‑панель:

- **Разделение состояний**: состояние формы (текущие значения полей) и состояние UI (открыт/закрыт сайдбар) разделены, что позволяет корректно реализовать сброс и применение без побочных эффектов.
- **Работу с CSS‑переменными**: все настройки (цвета, отступы, размеры) управляются через CSS‑переменные на уровне приложения — это даёт гибкую кастомизацию без изменения DOM‑структуры.
- **Переиспользование UI‑kit**: компоненты (`Button`, `Select`, `RadioGroup`, `ArrowButton`, `Separator`, `Spacer`, `Text`) вынесены в отдельные модули и задокументированы в Storybook.

## Функциональные возможности

- При нажатии на «стрелку» открывается сайдбар с настройками, при повторном нажатии или клике вне сайдбар закрывается.
- При изменении настроек в сайдбаре они не применяются сразу.
- После нажатия на «применить» стили применяются к статье.
- При нажатии «сбросить» настройки в форме сбрасываются на начальные, которые были при открытии страницы, и стили применяются к статье.
- Настройки устанавливаются через CSS-переменные.

## Стек технологий и инструменты

- **Frontend**: React, TypeScript.
- **UI‑kit и компоненты**: переиспользуемые компоненты (`Button`, `Select`, `RadioGroup` и др.) с типизированными пропсами.
- **Документация компонентов**: Storybook (запуск: `npm run storybook`).
- **Инструменты качества**: ESLint, Prettier, Stylelint.

## Выводы по результатам проекта

- Разделение состояния формы и состояния UI позволило чётко разделить логику «что отображать» и «как хранить текущие значения».
- Использование CSS‑переменных дало гибкий способ кастомизации без необходимости менять структуру DOM или писать сложные inline‑стили.
- Реализация подписки/отписки через `useEffect` исключила утечки памяти и дублирование слушателей при частых открытиях/закрытиях панели.
- Строгая типизация TypeScript и единый стиль именования сделали код предсказуемым и удобным для рефакторинга.
- Переиспользование компонентов UI‑kit ускорило сборку интерфейса и обеспечило визуальную консистентность.
